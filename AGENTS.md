# Rewrite contributor guide

This is a separate Git repository and Go module. `docs/dev/rewrite-plan.md` is the runtime contract; `docs/dev/migration-plan.md` is a separate removable utility, not startup behavior.

- Support Linux only. Use Linux process identity, terminal, and locking APIs directly; do not add macOS/Windows fallbacks or portability abstractions.
- Run `make test` after changes; `make check` also formats, race-tests, and builds.
- `make` prefers this repository's `.tools/go`, then the parent's toolchain. Use `make install-go` for a standalone checkout.
- Development builds are named `devbox-neo`. Their default home is `~/.devbox-neo`; `--home` takes priority over `DEVBOX_HOME`. The conventional old `~/.devbox` and its descendants are rejected even when explicitly selected. Container/session names use `devbox-<folder>-<12-hex-hash>` with `.profile-<name>` / `.project` suffixes; Docker ownership labels and image tags retain the separate `devbox-rewrite` namespace. Names never prove ownership. This naming change requires a clean session reset; do not add automatic migration or adoption. Tests must use temporary homes, never the user's current home or Docker resources.
- Keep lifecycle generic: no harness-name branches, old-schema readers, or config reloading in execution. Pi's built-in launch defaults to `--tui-mode fullscreen`; later harness arguments can override it.
- Use `commanderror.Error`/`Step` for actionable failures and preserve their causes. `cli.Execute` owns error rendering; human output uses short `Error:` messages, separate target context, and labeled `Step.Reason` commands. Keep codes/operation metadata in JSON. Generic creation hints show only `create <folder>`, without profile flags. Missing-environment and project-owner hints retain the entered folder spelling; filesystem identity stays canonical. Exact session/transfer selectors remain intact. Mark sequential/alternative reasons with `Then`/`Or`; do not embed next-command strings into errors or render them inside handlers. Missing-file control flow must remain distinct from invalid state; use `errors.Is` when consuming wrapped lookup errors. The executable remains `devbox-neo`; a doctor command is not planned.
- Images have one ownership contract: optional user Dockerfile base, then Devbox runtime and harness installation. Do not reintroduce `Dockerfile.full` or a user-owned runtime branch.
- Derive managed harness mount parents through `Definition.MountParents`. Image-only ancestors belong in the mandatory runtime layer; bind-backed ancestors belong in recorded create/start preparation. Do not patch harness names, recursively chown mounted state, or recreate missing durable roots.
- Session mutation requires external operation locks; labels, not names, prove Docker ownership. New-session creation is explicit: `create <folder>` prepares and leaves a stopped environment without launching its harness; `open`/`start` require an existing session and never create a new one. Container-setting flags belong to `create`/`recreate`; `open` accepts only launch settings, continuation, and harness arguments. Both open/start retain recorded missing-container recovery. `create` never overwrites an existing session.
- `environment.Inputs` is the shared source for aggregate fingerprints and detailed drift reasons. Session record schema 2 requires its complete applied snapshot; older records require a clean development reset, not compatibility readers or migration. Keep image/container inputs fixed until creation/recreation commits, and advance runtime inputs with their fingerprint through `Record.ApplyRuntime`. Never infer old inputs from current source files or add independent drift rules to CLI rendering.
- `app/transfer.go` owns the clone/relocate state machine. One external `state/transfers/<source-container>.json` journal reserves both endpoints; ordinary mutations use `Locked.Load` to reject pending transfers. Never repeat state copying after destination commitment, or delete the journal with source state.
- `resource` owns profile/project creation and source edits. Use external configuration-owner locks and no-replace publication for new directories/files. `create` stays sparse; `init` never refreshes existing artifacts. Source copies preserve expressions and use `artifact.SourceTree`; project inheritance previews use the normal resolver. Numbered config menus keep raw local values separate from effective/redacted display data; each completed operation saves immediately through `resource.SetConfigField`, the existing owner lock, and same-field conflict checks. Back only navigates; do not add a draft/confirmation stage for setting edits. Overview entry sources come from `artifact.Trace.EntrySources`, recorded during resolution; never infer entry ownership by matching values. Editors still expose only the selected layer's entries.
- Shell completion is read-only: bypass `store.Open` and locking record readers; never seed state or create locks on Tab. Name suggestions are lookup hints, not ownership proof. Use bounded installation-filtered Docker inventory only for live container targets, and tolerate unavailable sources without diagnostics. Generated scripts register existing `dbx` shortcuts without defining or changing them.
- Terminal display metadata is invocation-local: capture the allowlist in the CLI, supply defaults only to the temporary creation plan, and refresh it through attached-command exec overrides. Keep it out of desired configuration, fingerprints, and saved env-source references; do not change recorded shell argv or import host dotfiles.
- Never persist env/auth values in session records or print them in diagnostics. Sensitivity is by field: names, paths, networks, argv, and ordinary settings are public, including `${env:...}` substitutions. Config env recovery uses exact source-entry references and keyed fingerprints; invocation-only env requires explicit recreation after container loss.
- Runtime guidance is embedded from `docs/` and `internal/assets/`; built-in Pi/OpenCode `skills/devbox/SKILL.md` defaults link to `/devbox`. Init must leave this skill inherited, not copy it into profile/project config; explicit user overrides remain supported. Keep these inputs and network-fact paths aligned when container behavior changes.
- Keep tests and guide/reference/architecture docs aligned. Record unpassed acceptance gates honestly in `docs/dev/progress.md`.
- Migration logic belongs only in dedicated `migrations.go` files inside the removable migration package.
